## 1. 这套系统是什么

**一句话**:让 lisom.work / csu.lisom.work 的 HTTPS 证书永不过期,且基本不用人管。

**为什么需要它**:免费证书有效期只有 90 天,过期后网站 HTTPS 直接报错。过去每 3 个月要手动重做一遍(申请→手动加解析→下载→上传),2026-10-06 建成自动化后,人只需要在最后一步"上架"时出现 2 分钟。

**链路(记住星号那一点就够)**:

```
互联网 ──► natcross 边缘 (47.238.204.197, nginx)
           ★ TLS 在这里终结,证书装在 natcross 这一侧 ★
              │ 隧道
              ▼
        lab-bio（证书在这里自动申请）
              │
              ▼
        Caddy :8880 ──► 各服务(landing / gitea / rstudio / shiny …)
```

关键记忆点:**证书不在 lab-bio,在 natcross 边缘**。所以自动签出证书后,需要"送上 natcross"——这就是唯一的人工步骤。

## 2. 系统每天自动做什么(不用你管)

| 时间 | 动作 |
|---|---|
| 每天 02:04 / 08:04 / 14:04 / 20:04 | acme.sh 检查证书是否进入续期窗口(剩约 30 天时**自动重签**) |
| 每次续签成功后 | 自动校验新证书(非空/可解析/域名匹配/公私钥配对)→ 自动发「🔔 请上架」→ 文件就位 |
| 每天 08:07 | 监控巡检:边缘指纹 vs 本地最新、证书链完整性、续期钩子状态、剩余天数 → 全好则发「✅ 心跳」 |
| 任何异常 | 每天一条「⚠️ 告警」直到恢复 |

**90 天循环长这样**:签发 → (约第 60 天)自动重签 + 通知你上架 → 你 2 分钟 → 监控确认 → 到期前新证书早已在岗。

## 3. 你唯一的常规操作:收到「🔔 请上架」后的 2 分钟

> 触发频率:约每 90 天一次。**通知消息里自带同样步骤**,照着做即可。

**① 取件**(在你 Mac 的终端里粘贴):

```bash
scp lab-bio:~/manage/lisom-cert/fullchain.pem lab-bio:~/manage/lisom-cert/private.key ~/Downloads/
```

**② 上架**(浏览器打开 natcross 控制台):

| 步骤 | 操作 |
|---|---|
| 1 | 进入「映射」→ 找到 **lisom.work** 那个映射 → 修改 |
| 2 | 「pem 框」:用文本编辑器打开 `~/Downloads/fullchain.pem`,**全文**粘贴(以 `-----BEGIN CERTIFICATE-----` 开头) |
| 3 | 「key 框」:粘贴 `~/Downloads/private.key` 全文(以 `-----BEGIN RSA PRIVATE KEY-----` 开头) |
| 4 | 保存;**对 csu.lisom.work 那个映射重复 1–4** |

**③ 复检**:等 1–5 分钟(natcross 是异步生效),执行:

```bash
ssh lab-bio '~/manage/appnet/scripts/cert-monitor.sh; echo "exit=$?"'
```

`exit=0` = 全部一致,完成。(注:手动跑监控会额外触发一条心跳消息,正常。也可以什么都不做,等第二天 08:07 的心跳确认。)

**三个注意**:
- **两个映射都要贴**(lisom.work 和 csu.lisom.work),漏一个监控会点名那一个
- **key 必须是 `.key` 扩展名的文件**:natcross 按文件扩展名校验,`.pem` 会被拒(这就是文件叫 `private.key` 而不是 `privkey.pem` 的原因)
- 别从旧文件夹拿文件:通知发出后 `~/manage/lisom-cert/` 里的才是最新的

## 4. 你会收到的消息及对策(速查表)

| 消息(飞书) | 含义 | 你要做什么 |
|---|---|---|
| `✅ lisom 证书监控心跳:剩 N 天(每日一条,断更即异常)` | 一切正常 | 什么都不用做;若某天没收到 → §5.1 |
| `🔔 lisom 新证书已签发(至 …,指纹 …)` | 自动续签成功,等上架 | §3 两分钟 |
| `⚠️ …边缘证书与本地最新签发不一致(可能已续签未上架)` | 新证没贴上去,或只贴了一个映射 | 重做 §3;等 5 分钟再看 |
| `⚠️ …边缘只下发了叶子证书(链不完整…)` | 上架时**没贴全文**(漏了中间证书) | 重做 §3,确认 pem 框贴的是 fullchain **全文** |
| `⚠️ …链核验异常(连接抖动…)` | 网络抖动,没能读到链 | 大概率次日自愈;连续出现再查 natcross |
| `⚠️ …证书仅剩 N 天到期` | 续期/上架卡住了 | **优先处理** → §5.3 |
| `⚠️ …DNS 解析失败 / 边缘连接失败` | 解析或 natcross 边缘异常 | 查 DNSPod 记录是否还在、natcross 是否正常 |
| `⚠️ acme.sh reloadcmd 缺失或不可执行` | lab-bio 上钩子丢了(如仓库搬家) | §5.5 |
| `❌ lisom 证书交付:…(缺失/为空/不配对/域名不符)` | 自动交付环节自检失败 | 到 lab-bio 看 `~/manage/lisom-cert/` 与日志 → §5 |

## 5. 出问题怎么办(排查手册)

### 5.1 早上没收到心跳
1. 飞书群里的机器人还在吗?(被移出群/删除了机器人 → 收不到任何消息)
2. 手动发一条测试:
   ```bash
   ssh lab-bio '~/manage/appnet/scripts/cert-notify.sh "手动测试消息"'
   ```
   收到 → 通道没问题,是监控侧问题;收不到 → 通道坏了,看第 3 步
3. 看日志里最近的发送失败记录:
   ```bash
   ssh lab-bio 'tail -20 ~/manage/appnet/logs/cert.log'
   ```
   若见 `通知发送失败` → webhook 可能失效:飞书群 → 设置 → 群机器人 → 重新复制 webhook(如重设了签名密钥也要一并更新),写进 lab-bio 的 `~/manage/secrets/lisom.env`(字段 `FEISHU_WEBHOOK` / `FEISHU_SECRET`),再测一次
4. 若手动跑监控都不报错、只是没消息 → 直接看日志最后一行判断状态

### 5.2 反复收到「未上架 / 不一致」
- 确认**两个**映射都贴了、都点了保存
- 保存后**等 1–5 分钟**再判断(异步生效)
- 对比是不是最新文件:边缘指纹 vs 本地指纹:
  ```bash
  # 边缘实际证书(Mac 上跑)
  echo | openssl s_client -connect 47.238.204.197:443 -servername lisom.work 2>/dev/null | openssl x509 -noout -dates -fingerprint -sha256
  # lab-bio 本地最新签发
  ssh lab-bio 'openssl x509 -in ~/.acme.sh/lisom.work/fullchain.cer -noout -fingerprint -sha256'
  ```
  两个指纹一致 = 已生效;不一致 = 贴的不是最新那份

### 5.3 应急:证书已经快到期 / 已过期
1. 先看 lab-bio 上有没有现成的新证书:
   ```bash
   ssh lab-bio 'ls -l ~/manage/lisom-cert/ && openssl x509 -in ~/manage/lisom-cert/fullchain.pem -noout -dates'
   ```
   有且未过期 → 直接 §3 取件上架
2. 没有 → 强制重签:
   ```bash
   ssh lab-bio '~/.acme.sh/acme.sh --renew --force -d lisom.work -d "*.lisom.work"'
   ```
   成功 → §3;失败看它的输出与 `~/.acme.sh/lisom-issue.log`
3. 连签发都失败(DNSPod/网络问题)→ 备用通道:acmessl 平台可手工签(见台账;或联系协助)

### 5.4 DNSPod 的 API token(自动签发的"钥匙")
- 位置:`lab-bio:~/.acme.sh/account.conf`(600 权限,不在 Git 里)
- **不要去 DNSPod 控制台删除/重置它**——删了自动续期立刻断
- 确需更换令牌:DNSPod 新建 token → 更新 account.conf 里的 `DP_Id`(ID)与 `DP_Key`(密钥)→ 强制重签一次验证(§5.3 第 2 步)→ 旧 token 再删

### 5.5 搬家了(换服务器 / 仓库挪位置)
- 要搬的:① `~/.acme.sh/` 整个目录 ② `~/manage/secrets/lisom.env` ③ `~/manage/appnet/scripts/cert-*.sh`(在仓库里)④ 两个 cron 行 ⑤ 重装 natcross 客户端
- 搬完必做一步(acme.sh 的续期钩子里是**绝对路径**,路径变了要重挂):
  ```bash
  ~/.acme.sh/acme.sh --install-cert -d lisom.work \
      --key-file "$HOME/manage/lisom-cert/private.key" \
      --fullchain-file "$HOME/manage/lisom-cert/fullchain.pem" \
      --reloadcmd "$HOME/manage/appnet/scripts/cert-deliver.sh"
  ```

### 5.6 从零重建(极端情况)
最小步骤:装 acme.sh → 签发(Let's Encrypt, DNS-01, DNSPod token)→ `--install-cert` 挂钩子(见 §5.5)→ 三个脚本放回 `scripts/` → 恢复 cron 与 secrets。完整过程见设计文档 `docs/specs/2026-10-06-lisom-cert-automation-design.md` §2.1。

## 8. 原理速览(想弄懂再读)

- 免费证书来自 **Let's Encrypt**;流程是标准协议 ACME:申请 → 按 CA 要求,在 `_acme-challenge.lisom.work` 放一条随机 TXT 记录(证明域名归你)→ CA 查验通过 → 签发。acme.sh 用 DNSPod API 自动完成"放记录/删记录",所以能无人值守。
- 证书为什么必须人工送上 natcross:因为 TLS 在 natcross 边缘终结,它的证书只能通过控制台上传(该平台没有公开上传 API;全自动方案 B1 待评估,见设计文档 §2.3)。
- 为什么 key 文件必须 `.key` 后缀:natcross 上传控件按扩展名校验(`.pem`/`.key` 两种框)。

---

## 9. 安全守则(两句话)

- **两把钥匙永不外传**:DNSPod token(能改整个域名解析)与飞书 webhook+secret——只存在 lab-bio 的两个 600 权限文件里,**绝不粘进聊天/issue/仓库**(仓库可能被公开)。
- 私钥副本(如 `~/Downloads/` 里的)用完即删;仓库 `.gitignore` 已拦截 `*.key`/`*.pem`。
